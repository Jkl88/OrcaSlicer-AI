# Выпуск плагинов AI Assist и Filament QR

Ветка `plugins-v2.5.0` — это официальный OrcaSlicer v2.5.0 (`40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`) плюс два
плагина, их тесты, манифест совместимости и CI. Исходники OrcaSlicer в ней не меняются, собственной сборки
программы нет: плагины ставятся в официальный OrcaSlicer 2.5.0 или новее.

## Что входит в релиз

| Файл | Назначение |
|---|---|
| `orca_ai_assist.py` | Плагин AI Assist |
| `orca_filament_qr.py` | Плагин Filament QR |
| `compatibility.json` | Версия OrcaSlicer, на которую рассчитаны плагины, нужные функции API, версии и SHA-256 плагинов, статус проверки по платформам |
| `SHA256SUMS` | Контрольные суммы всех файлов релиза |

У каждого плагина своя версия: она записана в заголовке файла (`# version = "..."`) и в `compatibility.json`.

## Статусы платформ

В `compatibility.json` для каждой платформы записан один из статусов:

- `passed` — плагин проверен вручную на официальном OrcaSlicer этой платформы по списку ниже;
- `failed` — проверка выявила проблему;
- `not-tested` — проверки не было. Это честный статус, а не ошибка: автотесты CI проверяют логику плагинов
  без OrcaSlicer, а работу внутри программы подтверждает только ручная проверка.

## Ручная проверка на OrcaSlicer 2.5.0

1. Установите оба `.py` из артефакта CI `orca-plugins-<commit>` через окно Plugins и подтвердите запрошенные
   разрешения.
2. **AI Assist.** Запустите анализ с действующим ключом, отметьте одну строку процесса и одну строку пластика.
   - «Применить: Процесс» → окно подтверждения → «Да». Вкладка процесса помечена как изменённая, значение новое.
   - «Применить: Пластик» → «Нет». Ничего не меняется.
   - Поменяйте отмеченное значение вручную и снова нажмите «Применить». Должно появиться сообщение, что
     значения изменились после анализа.
3. **Filament QR.** Создайте катушку, отсканируйте её с телефона по локальной сети для слота 2. Появится окно
   подтверждения, после «Да» профиль будет выбран в слот 2. Если вкладка пластика содержала несохранённые
   правки, OrcaSlicer спросит, что с ними делать.
4. Выключите и снова включите каждый плагин. Закройте OrcaSlicer во время запроса к Gemini. Программа не должна
   зависнуть или упасть.
5. Запишите результат в `plugins/compatibility.json` (`platforms.<платформа>`: `passed` или `failed`), выполните
   `python3 scripts/plugin_release.py check` и закоммитьте.

## Порядок выпуска

1. Поднимите версию изменённого плагина в заголовке файла и в `plugins/compatibility.json`.
2. `python3 scripts/plugin_release.py update-hashes` и `python3 scripts/plugin_release.py check`.
3. Проверьте локальную сборку: `python3 scripts/plugin_release.py build --out dist`.
4. Закоммитьте, дождитесь зелёного workflow **Plugins**, проведите ручную проверку.
5. Создайте и отправьте тег `plugins-vX.Y.Z`. Workflow сам создаст GitHub Release с файлами из `dist/`.
   Повторный запуск для того же тега ничего не перезаписывает: если в релизе уже лежат другие файлы,
   workflow завершится ошибкой, и нужен новый тег.

Создание и отправку тега выполняет мейнтейнер вручную.
